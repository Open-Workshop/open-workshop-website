# JS Unit Tests

Этот каталог содержит поведенческие unit-тесты для браузерного JavaScript сайта.
Они нужны, чтобы не проверять реализацию через `assertIn("кусок строки", script)`,
а фиксировать ожидаемое поведение модулей на входах и выходах.

## Запуск

```bash
node --test tests/js
```

Тесты используют встроенный раннер Node.js `node:test`. Дополнительные npm-зависимости не нужны.

Для быстрой проверки синтаксиса:

```bash
node --check tests/js/catalog-core.test.js
node --check tests/js/cards.test.js
```

## `catalog-core.test.js`

Проверяет чистую каталожную логику из `website/assets/scripts/catalog-core.js`.

Покрытые сценарии:

- `catalog_kind=modpack` и `sgame=yes` остаются в режиме выбора игры и запрашивают `/games`.
- `catalog_kind=modpack` и `sgame=no` запрашивают `/modpacks`, переносят выбранную игру в `game_id` и сохраняют modpack-фильтры.
- Моды нормализуют зависимости, исключенные зависимости, исключенные конфликты, теги и adult-фильтр перед запросом `/mods`.
- Режим независимых модов удаляет dependency-фильтры из запроса.
- `game_type` и legacy `types` отправляются в manager API только для game feed.
- Сортировки приводятся к допустимым значениям отдельно для `game`, `mod` и `modpack`.
- Cleanup URL-параметров зависит от активного view, а не от случайного набора параметров.
- Сборщик request plan не мутирует входной объект настроек.

## `cards.test.js`

Проверяет поведение `window.Cards` из `website/assets/scripts/vendors/cards.js`
в изолированном VM-контексте с минимальными DOM/fetch-заглушками.

Покрытые сценарии:

- `Cards.setterImgs` собирает id видимых карточек и пропускает `.card--placeholder`.
- `sourceItems` из ответа каталога имеют приоритет над DOM-сканированием.
- Устаревший catalog request token отменяет запрос ресурсов.
- `Cards.create` помечает adult-карточки классом `card--adult` и строит ссылки modpack-карточек на `/modpack/{id}`.

## Когда добавлять JS unit-тест

Добавляйте тест сюда, если изменение касается логики браузерного JS, которую можно проверить без реального браузера:

- нормализация query/API параметров;
- выбор endpoint;
- трансформация данных перед рендером;
- защита от stale async-запросов;
- создание DOM-структуры с предсказуемыми классами/ссылками.

Если нужен настоящий layout, hover, viewport или CSS cascade, лучше использовать браузерные/e2e тесты, а не расширять эти VM-заглушки до полноценного браузера.
